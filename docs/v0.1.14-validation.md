# AKRAT v0.1.14 — optimisation des dépendances

Branche : `v0.1.14-dependency-optimization`
Base : commit v0.1.13 `3cec46a80a451ab834a91a348a325b15f08e8361`
Version des paquets : `0.1.14`

## Changements

- Tokio n'active plus par défaut l'ensemble de ses fonctionnalités dans le workspace. Chaque paquet AKRAT déclare celles dont son code a besoin.
- `akrat-core` demande explicitement `iroh-base/key`. Le contrôle isolé a révélé que ses usages de `SecretKey` et `EndpointId` dépendaient auparavant de la fusion de fonctionnalités avec les autres paquets du workspace.
- Dioxus garde ses fonctionnalités `launch` et `lib`; les fonctionnalités `logger` et `devtools` ne sont plus demandées directement par AKRAT. Le backend desktop Dioxus active encore certaines fonctionnalités par ses propres dépendances, qui restent transitives.
- Les sept paquets Rust sont alignés sur `0.1.14`; les dépendances internes épinglées ont été mises à jour. Aucun protocole, comportement utilisateur ou primitive cryptographique n'a été modifié.

Le verrou Cargo retire les dépendances optionnelles devenues inutiles pour la sélection Dioxus d'AKRAT, dont `dioxus-logger` et `tracing-wasm`. Les profils Release et le nombre de jobs n'ont pas été modifiés.

## Validations locales

Environnement : WSL Linux avec `protoc` installé; les caches existants ont été conservés.

- `cargo check --locked -p <paquet> --all-targets` exécuté isolément pour les sept paquets : réussi.
- `cargo check --locked --workspace --all-targets` : réussi.
- `cargo check --locked --no-default-features -p akrat-desktop --features mobile` : réussi sur l'hôte Linux; cela ne remplace pas la compilation Android de CI.
- `cargo fmt --all -- --check` : réussi.
- `cargo clippy --locked --workspace --all-targets -- -D warnings` : réussi sous WSL.
- `cargo test --locked --workspace` : réussi, 123 tests au total, dont les tests de transport P2P, de relais, d'images, de fédération et d'updater.
- `cargo audit` : terminé avec six avis transitoires signalés comme avertissements par l'outil. Ils proviennent de l'ancienne chaîne native Wry/GTK et de macros de build; ils ne sont pas ajoutés à une liste d'exceptions.
- `cargo deny check -W unmaintained -W unsound --hide-inclusion-graph` : réussi, avec avertissements sur les versions dupliquées et les avis transitifs.
- `cargo deny check` sans options : échoue sur l'avis unsound `RUSTSEC-2026-0097` de `rand 0.7.3`, transitif de `wry → kuchikiki → selectors → phf_codegen`. Il n'existe pas de mise à jour compatible démontrée dans la chaîne Dioxus 0.7 utilisée ici; l'avis n'a pas été ignoré ni rétrogradé dans la configuration.
- `cargo machete` et `git diff --check` : réussis.

Les contrôles d'intégration complets ont été exécutés deux fois pendant la stabilisation; le passage final ci-dessus utilise les paquets versionnés `0.1.14`. Les tests de relais P2P et de messagerie hors ligne utilisent de vrais processus et sockets locaux.
