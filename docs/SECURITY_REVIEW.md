# Dependency security review

Checked with `cargo audit`, `cargo tree --target all`, and target-specific feature trees on 2026-11-10. The current lockfile has five transitive RustSec advisories. None is configured as ignored, and no advisory is suppressed. The shipped application target is `x86_64-pc-windows-msvc`.

| Advisory | Dependency path | Exposure in AKRAT | Status |
| --- | --- | --- | --- |
| [RUSTSEC-2025-0057](https://rustsec.org/advisories/RUSTSEC-2025-0057.html), unmaintained `fxhash 0.2.1` | `wry 0.53.5 → kuchikiki 0.8.8-speedreader → selectors 0.24.0 → fxhash` on the non-Windows desktop graph | `cargo tree --target x86_64-pc-windows-msvc -i fxhash` returns no path. It is not in the Windows target graph or shipped Windows executable. The app does not load remote HTML; message text is rendered as text. | No fixed fxhash release. Keep the target limitation documented and update the upstream selector/Wry chain when a compatible release is available. |
| [RUSTSEC-2024-0436](https://rustsec.org/advisories/RUSTSEC-2024-0436.html), unmaintained `paste 1.0.15` | `dioxus-desktop 0.7.10 → image 0.25.10 (default/default-formats → avif) → ravif 0.13.0 → rav1e 0.8.1 → paste` | Present in the Windows compile feature graph as a procedural macro; it is used to generate Rust code during compilation and is not a message parser or runtime crate in the shipped executable. | No fixed release reported. An upstream Dioxus/image feature change is the compatible path; no GUI stack migration was made for this alert. |
| [RUSTSEC-2024-0370](https://rustsec.org/advisories/RUSTSEC-2024-0370.html), unmaintained `proc-macro-error 1.0.4` | Linux GTK macros: `gtk3-macros 0.18.2 → proc-macro-error`; also `glib-macros 0.18.5 → proc-macro-error` | Linux-only GTK compilation graph. `cargo tree --target x86_64-pc-windows-msvc -i proc-macro-error` returns no path; it is not in the Windows build. | No patched version. | [RUSTSEC-2026-0097](https://rustsec.org/advisories/RUSTSEC-2026-0097), unsound `rand 0.7.3` | Build-time `selectors 0.24.0 → phf_codegen 0.8.0 → phf_generator 0.8.0 → rand 0.7.3` on the non-Windows graph | Build dependency only; the advisory's trigger additionally requires a custom logger calling the thread RNG during reseeding under specific conditions. AKRAT defines no such logger and this old RNG is not used by message crypto. No Windows target path appears. | Patch exists in newer rand lines, but the old code generator constrains this version. Update that build chain upstream. |

`cargo update` found no newer compatible Wry release within Dioxus Desktop 0.7.10's current constraints. Forcing newer GTK/GLib versions across GTK 0.18 bindings would create an incompatible graph and was not attempted. Moving to a different major Dioxus desktop stack could remove some paths but would be a larger framework migration requiring separate build/runtime validation. The direct text-only `arboard` dependency disables its optional image features. Cargo audit continues to print all five findings; the CI step does not use an ignore list or an allowlist.

The audit result does not establish that the cryptographic code is safe. Review the protocol and threat model separately; ML-KEM and the complete handshake/application wiring still need independent cryptographic review.
