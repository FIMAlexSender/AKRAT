# Dependency security review

Checked with `cargo audit` and `cargo tree --target all` on 2026-11-10. The current lockfile has five transitive RustSec advisories. None is configured as ignored, and no advisory is suppressed.

| Advisory | Dependency path | Exposure in AKRAT | Status |
| --- | --- | --- | --- |
| [RUSTSEC-2025-0057](https://rustsec.org/advisories/RUSTSEC-2025-0057.html), unmaintained `fxhash` | `wry → kuchikiki → selectors → fxhash` | Desktop webview/HTML selector support. AKRAT does not load arbitrary remote HTML; network message bodies are rendered as text. This limits the app-specific path but does not resolve maintenance risk. | No fixed fxhash release. A GUI stack update or upstream selector migration is needed. |
| [RUSTSEC-2024-0436](https://rustsec.org/advisories/RUSTSEC-2024-0436.html), unmaintained `paste` | `dioxus-desktop → image → ravif → rav1e → paste` | Procedural macro/build-time dependency; not a network message parser in the running app. | No fixed release reported. Updating the desktop/image stack is the practical path. |
| [RUSTSEC-2024-0370](https://rustsec.org/advisories/RUSTSEC-2024-0370.html), unmaintained `proc-macro-error` | Linux GTK bindings/macros → `glib-macros → proc-macro-error` | Build-time macro dependency in the GTK desktop target. | No patched version. Replacing or updating the Linux desktop dependency chain is required. |
| [RUSTSEC-2024-0429](https://rustsec.org/advisories/RUSTSEC-2024-0429.html), unsound `glib 0.18.5` | Linux GTK/Wry target | The reported undefined behavior is in `VariantStrIter` iterator methods. AKRAT's Rust app code does not call GLib APIs or those methods. The GTK tree is not built for the Windows target, but the full cross-platform dependency graph retains it. | Patched in `glib >=0.20`; the current GTK 0.18 chain constrains the version. No safe compatible override was found. |
| [RUSTSEC-2026-0097](https://rustsec.org/advisories/RUSTSEC-2026-0097), unsound `rand 0.7.3` | build-time `phf_codegen → selectors → kuchikiki → wry` | This advisory requires a custom logger to call the thread RNG during reseeding under specific log/getrandom conditions. The occurrence is in the desktop build dependency path; AKRAT does not define that custom logger and does not use this old rand crate in its message crypto. It is not part of the Windows runtime dependency graph. | Patched rand versions exist, but the old build-time generator chain controls this dependency. Updating that chain is needed. |

`cargo update` found no newer compatible Wry release within Dioxus Desktop 0.7.10's current constraints. Forcing newer GTK/GLib versions across the GTK 0.18 bindings would create an incompatible graph and was not attempted. Moving to a different major Dioxus desktop stack could remove some paths but would be a larger framework migration and requires separate build/runtime validation. The Windows release build still carries the Dioxus/Wry desktop stack; the GLib and legacy rand advisories are target-specific and are not compiled into the Windows app.

The audit result does not establish that the cryptographic code is safe. Review the protocol and threat model separately; ML-KEM and the complete handshake/application wiring still need independent cryptographic review.
