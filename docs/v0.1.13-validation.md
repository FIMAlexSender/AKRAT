# AKRAT v0.1.13 · validation et dépendances

État de ce rapport : 13 novembre 2026. Cette version est issue de la branche `v0.1.12-architecture-relay`. Le tag historique `v0.1.12` reste inchangé; les artefacts de cette version doivent être publiés sous le tag `v0.1.13` après validation de son commit exact.

## Changements livrés

- La politique locale des relais favorise les chemins directs, puis les relais marqués Favori, puis les relais autorisés. La sélection tient compte de la latence et évite les changements pour un gain inférieur à 50 ms lorsque les chemins ont le même niveau.
- Les relais favoris restent soumis à la politique d’autorisation existante. Un favori indisponible peut être remplacé par un relais autorisé; aucun relais exclu par la politique n’est ajouté comme solution de secours.
- L’interface Réseau expose cette règle. Les paramètres de relais continuent d’être conservés dans le coffre.
- La version Cargo passe à `0.1.13`. Le workflow de release copie le rapport de validation correspondant au tag au lieu d’un nom de version fixe.

## Contrôles locaux

Validation locale Windows, 13 novembre 2026 : `cargo fmt --all -- --check`, `cargo check --locked --workspace --all-targets`, `cargo clippy --locked --workspace --all-targets -- -D warnings` et `cargo test --locked --workspace` réussissent. La suite exécute 113 tests, dont les tests de transfert P2P par relais, de sélection du favori, de bascule sur relais autorisé, de fédération Mailbox, de livraison hors ligne, de coffre et de confiance cryptographique.

`cargo audit` ne signale aucune vulnérabilité; il rapporte six avertissements transitifs déjà présents (crates non maintenues ou alertes soundness). `cargo deny check -W unmaintained -W unsound --hide-inclusion-graph` réussit en laissant ces avertissements visibles. `cargo machete` ne détecte aucune dépendance directe inutilisée. La CI et l’inspection des artefacts multiplateformes restent à effectuer avant publication.

Le test d’intégration `crates/akrat-core/tests/relay_transport.rs::favorite_relay_is_preferred_for_an_open_p2p_path` démarre deux relais Iroh locaux, établit un flux chiffré entre deux endpoints et vérifie que le chemin sélectionné passe par le relais favori. Le test `endpoint_switches_to_an_allowed_relay_after_home_relay_fails` coupe le relais préféré et vérifie la livraison après bascule vers le relais autorisé.

## Portée

Windows x64, Linux x64 et Android sont les cibles CI de publication. macOS n’est pas compilé ni validé dans cette version. Les tests de relais locaux valident la sélection et le repli de chemins Iroh; ils ne constituent pas une mesure de disponibilité de relais publics sur Internet.
